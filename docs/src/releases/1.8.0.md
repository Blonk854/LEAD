# LEAD 1.8.0 (dev)

Release channel: **dev** · Version source of truth: `crates/zed/Cargo.toml`

This release focuses on making LEAD's agent both more capable (whole-PC tools,
hybrid orchestration) and more reliable over long sessions (automatic thread
rollover, context compaction, cross-session memory). All new powers ship behind
explicit switches and guard rails.

## Highlights

- **Guard-railed Unleashed access** — optional native tools that operate beyond the
  open project, behind a master switch and a confirm-on-escape permission model.
- **Hybrid Network Agent + local worker** — a strong network model orchestrates
  while your local LM Studio model executes delegated work via `spawn_agent`.
- **Auto thread rollover and hand-off** — long conversations roll into a fresh
  thread seeded with a hand-off summary, keeping local models performing well.
- **Local-agent memory and retrieval** — durable journal, project summaries, and
  a per-worktree document index.

## Guard-railed Unleashed access

Off by default. Enable in **Settings → AI → Unleashed**, or with the master
switch and the **Unleashed** (or **Hybrid**) agent profile:

```json
{
  "agent": {
    "full_access": {
      "enabled": true,
      "allowed_roots": [],
      "denied_roots": []
    }
  }
}
```

New native tools (hidden from the model while `enabled` is `false`):

- `run_code` — run Python, Node.js, PowerShell, or Bash source through an
  installed interpreter.
- `process_control` — inspect processes/system info, terminate a process, or
  list/start/stop Windows services.
- `http_request` — send generic HTTP/HTTPS requests.
- `computer_use` — capture the primary monitor and control the mouse/keyboard.
- Existing terminal and filesystem tools additionally accept authorized absolute
  paths outside project worktrees.

**Authorization policy (confirm-on-escape).** Paths in open worktrees and under
`allowed_roots` run without a prompt; absolute paths outside them trigger the
permission dialog. `denied_roots` and LEAD's built-in catastrophic-path denylist
always take precedence. Process termination and every screenshot/mouse/keyboard
action always prompt.

**Unbypassable protections.** Filesystem tools reject drive roots and protected
OS trees (Windows, Program Files, ProgramData); terminal checks reject drive
formatting, partition management, and recursive deletion aimed at protected
roots. Symlinked parents are canonicalized before policy is applied. These cannot
be disabled through settings.

Full detail lives in the repository at `docs/full-access.md`.

## Hybrid Network Agent + local worker

Hybrid mode uses a **network model as orchestrator** and your **local LM Studio
model as worker** via `spawn_agent`. With balanced delegation (the default),
execution tools are hidden from the orchestrator so heavy work is delegated to
the local subagent.

- Configure the network endpoint from the agent panel's **Network** settings
  (writes an `openai_compatible` provider with id `network-agent`).
- Set `agent.default_model` to your local worker model.
- Use the **`hybrid`** or **`write`** profile (must include `spawn_agent`).

Setup, tuning, and troubleshooting live in the repository at
`docs/local-agent-tuning-checklist.md`.

## Auto thread rollover and hand-off

When a conversation approaches the model's context window, LEAD generates a
hand-off summary and continues in a fresh thread. If an active `/goal` is
running, the new thread auto-resumes the work.

```json
{
  "agent": {
    "auto_thread_rollover": {
      "enabled": true,
      "context_fraction": 0.75
    }
  }
}
```

- `context_fraction` (0.1–0.95) is the share of the context window at which
  rollover triggers.
- Rollover skips subagents, already-rolled threads, and threads with fewer than
  two user turns.
- The manual token-limit callout is suppressed when auto-rollover is enabled.

## Local-agent memory and retrieval

LEAD persists cross-session state under `.local_agent/` in each worktree:

- `JOURNAL.md` — durable notes via the `append_to_journal` / `read_journal`
  tools.
- `project_summary.md` — latest compaction or rollover summary, injected into new
  threads.
- `rag.db` — local document index via `rag_ingest` / `rag_search` (uses LM Studio
  embeddings).

When using LM Studio models, LEAD proactively compacts in-thread context as the
window fills, not only on thread rollover.

## Settings added in 1.8.0

| Setting | Default | Purpose |
| --- | --- | --- |
| `agent.full_access.enabled` | `false` | Master switch for whole-PC tools |
| `agent.full_access.allowed_roots` | `[]` | Absolute roots that skip the escape prompt |
| `agent.full_access.denied_roots` | `[]` | Absolute roots that are always blocked |
| `agent.auto_thread_rollover.enabled` | `true` | Roll long threads into a fresh, seeded thread |
| `agent.auto_thread_rollover.context_fraction` | `0.75` | Context-window share that triggers rollover |
| `agent.network_agent.enabled` | `false` | Enable hybrid orchestrator + local worker |

## Agent profiles

- **Unleashed** — all IDE tools plus the whole-PC tools (`run_code`,
  `process_control`, `http_request`, `computer_use`).
- **Hybrid** — orchestrator/worker delegation with the whole-PC tools available.
- **Local Agent** (default), **Write** — unchanged lean/rich local tool sets.

## Build and install

- Executable: `target/x86_64-pc-windows-msvc/release/lead.exe`
- Installer: `target/LEAD-1.8.0-x86_64.exe`

Build both with `script/bundle-lead-windows.ps1` (add `-SkipBuild` to repackage
existing binaries, `-Install` to launch the installer afterward).
